# OmniNetSaasia
# MANDATO MAESTRO DE REEMPLAZO POR BIBLIOTECAS PROBADAS

**Repositorio:** `galleguillosdavid-coder/OmniNetSaasia`

**Objetivo:** reemplazar progresivamente el código artesanal del proyecto por bibliotecas/proyectos maduros, mantenidos y ampliamente utilizados, conservando las capacidades funcionales y reduciendo al mínimo el código propio.

---

# 1. ORDEN SUPREMO

A partir de este documento, Antigravity debe operar bajo la siguiente regla:

> **No desarrollar desde cero una funcionalidad que una biblioteca madura y apropiada ya resuelva correctamente.**

Antes de escribir código propio para una capacidad, realizar esta secuencia:

```text
REQUERIMIENTO
      ↓
¿Existe biblioteca madura?
      ↓
¿Tiene licencia compatible?
      ↓
¿Está mantenida?
      ↓
¿Tiene adopción/evidencia suficiente?
      ↓
¿Cubre realmente nuestra necesidad?
      ↓
SÍ ─────────────── NO
 ↓                  ↓
ADOPTAR             desarrollar mínimo necesario
```

                    OmniNet

# 3. REGLA DE NO REINVENCIÓN

Eliminar o reemplazar cualquier implementación propia cuando exista una alternativa suficientemente madura.

Ejemplos:

```text
HTTP propio
→ httpx / aiohttp / FastAPI / Uvicorn

validación propia
→ Pydantic

criptografía propia
→ cryptography

JWT propio
→ PyJWT / Authlib

password hashing
→ Argon2id mediante argon2-cffi

WebSocket propio
→ websockets / FastAPI

retry propio
→ tenacity

CLI propia compleja
→ Typer / Click

logging propio
→ logging estructurado / structlog

SQLite wrapper propio
→ SQLAlchemy / SQLModel

PostgreSQL propio
→ psycopg / SQLAlchemy

Supabase REST manual
→ SDK oficial de Supabase cuando resulte apropiado

telemetría propia
→ OpenTelemetry

métricas propias
→ Prometheus client

scheduling propio
→ APScheduler

filesystem abstractions
→ pathlib

subprocess management complejo
→ subprocess + psutil

detección hardware propia
→ APIs/librerías específicas maduras

backup propio
→ Restic

antivirus propio
→ ClamAV / Microsoft Defender

YARA engine propio
→ yara-python

network packet inspection
→ Scapy cuando corresponda

DNS
→ dnspython / APIs del sistema

packet measurement
→ herramientas del sistema especializadas

agent orchestration propia
→ framework maduro solamente si cumple requisitos reales
```

Estas son **candidatas iniciales**, no autorizaciones automáticas. Antigravity debe verificar versión, licencia, mantenimiento y compatibilidad antes de incorporarlas.

# 37. API DE COMPATIBILIDAD

Aunque internamente se reemplacen componentes, conservar inicialmente las APIs públicas.

Ejemplo:

```text

```

puede continuar existiendo, pero internamente:

```text
netopt.diagnose()
      ↓
library_adapter
      ↓
mature_library
```

Esto permite migrar sin romper todo el proyecto simultáneamente.

---

# 38. ADAPTER PATTERN

Toda biblioteca externa importante debe estar detrás de un adapter cuando exista riesgo de dependencia directa en todo el proyecto.

Ejemplo:

```python
class NetworkDiagnostics:
    def diagnose(self):
        ...
```

Implementación:

```text
NetworkDiagnostics
        ↓
PsutilAdapter
        ↓
psutil
```

No:

```text
100 archivos
 ↓
psutil directamente
```

Esto permite reemplazar dependencias futuras sin reescribir OmniNet.
