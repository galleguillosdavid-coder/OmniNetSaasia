# 4. SEGUNDA FASE — CONTROL DE VERSIONES

Existe una inconsistencia que debe resolverse.

El README declara:

```text
OmniNet AI Agent Pro v2.9.6
```

pero `main.py` contiene:

```python
VERSION = "2.9.0"
```

Y `pyproject.toml` declara:

```toml
version = "2.9.6"
```

Esto debe quedar unificado.

## Mandato

Determina cuál es la versión real del sistema y modifica:

- `main.py`
- `pyproject.toml`
- `README.md`
- documentación relacionada
- endpoints `/health`
- banners
- metadatos
- tests que dependan de versión

para que exista **una única fuente de verdad de versión**.

No mantener números de versión duplicados manualmente si puede evitarse.

Preferencia:

```python
VERSION = ...
```

y que los demás componentes consuman esa versión.

# 6. ESTADO EPISTEMOLÓGICO

El proyecto utiliza expresiones como:

```text
VERIFICADO
```

para numerosas capacidades.

Esto debe endurecerse.

Cada capacidad debe clasificarse como uno de:

```text
IMPLEMENTED
TESTED
DRY_RUN_TESTED
MOCK_TESTED
HARDWARE_VERIFIED
INTEGRATION_VERIFIED
PRODUCTION_VERIFIED
DOCUMENTED_ONLY
NOT_VERIFIED
```

Ejemplo:

```text
Wi-Fi 7
IMPLEMENTED: sí
TESTED: sí
HARDWARE_VERIFIED: no
PRODUCTION_VERIFIED: no
```

No debe afirmarse:

```text
Wi-Fi 7 4096-QAM verificado
```

si únicamente existe una función que calcula o comprueba parámetros teóricos.
